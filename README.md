# SkyCompute Frontend — Cloud & GPU Rental Client

Вебклієнт для хмарної платформи оренди серверів та прискорювачів **SkyCompute**, розроблений у межах Лабораторної роботи №4 курсу «Вебпрограмування» (НаУКМА).

Клієнт демонструє отримання даних з бекенду через **CORS (Cross-Origin Resource Sharing)**, роботу каталогу, фільтрацію, пошук, пагінацію, перегляд детальної конфігурації сервера та обробку єдиного формату помилок REST API.

---

## Адреси та порти

| Сервіс | Адреса | Порт | Призначення |
| --- | --- | --- | --- |
| **Frontend** (цей репозиторій) | `http://localhost:3000` або `http://127.0.0.1:3000` | `3000` | Клієнтський вебінтерфейс |
| **Backend** (Django REST API) | `http://127.0.0.1:8000/api/v1/` | `8000` | REST API для датацентрів, вендорів та інстансів |

Бекенд налаштовано за допомогою бібліотеки `django-cors-headers` з дозволом запитів із `http://localhost:3000` та `http://127.0.0.1:3000`.

---

## Функціональні можливості

1. **Каталог серверних потужностей:**
   - Отримання списку інстансів з ендпоінту `GET /api/v1/instances`;
   - Живий пошук за назвою інстансу або моделлю GPU (параметр `search`);
   - Фільтрація за робочим навантаженням: `General`, `Compute-Optimized`, `Accelerator (GPU/AI)`;
   - Фільтрація за датацентрами та вендорами (списки підвантажуються динамічно з `GET /api/v1/datacenters` та `GET /api/v1/vendors`);
   - Сортування за погодинною вартістю оренди та обсягом RAM (`price`, `-price`, `ram_gb`, `-ram_gb`);
   - Посторінкова пагінація (`page`, `limit`).
2. **Детальна модальна картка сервера:**
   - При натисканні на «Деталі →» виконується запит `GET /api/v1/instances/{id}`;
   - Відображаються повні характеристики: vCPU, RAM, GPU, тип і розмір накопичувача, пропускна здатність мережі, регіон, місто та країна датацентру, архітектура вендора.
3. **Інтерактивна панель перевірки CORS та обробки помилок:**
   - Кнопка виклику `DELETE /api/v1/datacenters/1` — демонструє бізнес-правило та статус `409 Conflict` (заборона видалення зайнятого датацентру);
   - Кнопка виклику `POST /api/v1/datacenters` з невалідними даними — демонструє статус `400 Bad Request` та валідаційні повідомлення;
   - Кнопка виклику `GET /api/v1/instances/9999` — демонструє статус `404 Not Found`.

## Як запустити проєкт

### Передумови
* Встановлений [Node.js](https://nodejs.org/) (версія 18 або новіша).
* Запущений Django бекенд SkyCompute на порту `8000`.

### 1. Запуск бекенду (в окремому терміналі)
У репозиторії бекенду виконайте:

```bash
# Активація віртуального оточення
.venv\Scripts\activate   # Windows
# source .venv/bin/activate  # Linux/macOS

# Застосування міграцій та завантаження тестових даних
python manage.py migrate
python manage.py loaddata sample_data

# Запуск сервера
python manage.py runserver 127.0.0.1:8000
```

### 2. Запуск фронтенду

У кореневій директорії цього репозиторію:

```bash
# Встановлення залежностей (Vite)
npm install

# Запуск сервера розробки на порту 3000
npm run dev
```

Після запуску відкрийте браузер за адресою:
👉 **[http://localhost:3000](http://localhost:3000)**

### Альтернативний запуск без `npm install`
Якщо ви хочете запустити проєкт як звичайний статичний сайт без попереднього встановлення залежностей:

```bash
# За допомогою Node.js npx serve
npx serve -l 3000

# або за допомогою Python
python -m http.server 3000
```
